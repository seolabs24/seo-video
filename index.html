Section 01

Video File Preparation

Before any code is written, the video must be exported in the correct formats, resolutions, and sizes. The current 13 MB source file will cause LCP failure on mobile. All four output files listed below must be produced before upload.

Required Output Files

FilenameFormatResolutionMax SizeFPSAudio
hero-desktop.webmWebM / VP91280×7203 MB24Removed
hero-desktop.mp4MP4 / H.2641280×7204 MB24Removed
hero-mobile.webmWebM / VP9854×4801.5 MB24Removed
hero-mobile.mp4MP4 / H.264854×4802 MB24Removed
hero-poster.webpWebP1920×1080150 KB——

FFmpeg Commands

Use the following FFmpeg commands to produce all four video files from the original source. Replace source.mov with the actual filename.

bashterminal
# ── DESKTOP WebM (VP9) ──────────────────────────────────────
ffmpeg -i source.mov \
  -c:v libvpx-vp9 \
  -crf 32 \
  -b:v 0 \
  -vf scale=1280:720 \
  -r 24 \
  -an \
  -deadline good \
  -cpu-used 2 \
  hero-desktop.webm

# ── DESKTOP MP4 (H.264) ─────────────────────────────────────
ffmpeg -i source.mov \
  -c:v libx264 \
  -crf 26 \
  -preset slow \
  -vf scale=1280:720 \
  -r 24 \
  -an \
  -movflags +faststart \
  hero-desktop.mp4

# ── MOBILE WebM (VP9) ───────────────────────────────────────
ffmpeg -i source.mov \
  -c:v libvpx-vp9 \
  -crf 36 \
  -b:v 0 \
  -vf scale=854:480 \
  -r 24 \
  -an \
  -deadline good \
  -cpu-used 2 \
  hero-mobile.webm

# ── MOBILE MP4 (H.264) ──────────────────────────────────────
ffmpeg -i source.mov \
  -c:v libx264 \
  -crf 28 \
  -preset slow \
  -vf scale=854:480 \
  -r 24 \
  -an \
  -movflags +faststart \
  hero-mobile.mp4

# ── POSTER IMAGE ────────────────────────────────────────────
# Extract best frame (adjust 00:00:02 to the desired timestamp)
ffmpeg -i source.mov -ss 00:00:02 -vframes 1 hero-poster.png
# Then convert to WebP at high quality
cwebp -q 85 -resize 1920 1080 hero-poster.png -o hero-poster.webp
-movflags +faststart is mandatory for MP4. This moves the MP4 metadata (moov atom) to the beginning of the file so the browser can start playing before the entire file is downloaded. Without it, the browser must download 100% of the file before any playback begins.
Verify output file sizes with ls -lh hero-*.webm hero-*.mp4 before uploading. If desktop WebM exceeds 3 MB, increase CRF to 34–36 and re-encode.

Attribute Reference

AttributeValueWhy it is required
autoplaybooleanStarts playback immediately. Requires muted or browsers block it.
mutedbooleanRequired for autoplay in all browsers. Without it, Chrome, Safari, and Firefox block autoplay.
loopbooleanRestarts video when it ends. Required for a continuous brand atmosphere loop.
playsinlinebooleanRequired on iOS Safari. Without it, iPhone forces fullscreen playback.
width / height1280 / 720Reserves space in the layout before the video loads. Prevents CLS (Cumulative Layout Shift).
poster/assets/images/hero-poster.webpStatic image shown instantly on load. This is your LCP element — it must load fast.
aria-hidden"true"Hides decorative video from screen readers. The video carries no information — the H1 does.
data-*file pathsCustom attributes read by hero-video.js to inject the correct source per device.

Section 05

JavaScript — Responsive Source Swap

This script reads the video element's data-* attributes and injects the correct <source> tags based on screen width. It runs on DOMContentLoaded so the poster image has already started loading by the time the script executes.

javascripthero-video.js
/**
 * Hero Video — Responsive Source Swap
 *
 * Selects desktop or mobile video files based on viewport width.
 * Also handles orientation change and iOS Low Power Mode fallback.
 *
 * Breakpoint: 768px (adjustable via MOBILE_BREAKPOINT)
 */

(function () {
  'use strict';

  const MOBILE_BREAKPOINT = 768; // px — adjust to match your CSS breakpoint

  function isMobile() {
    return window.innerWidth <= MOBILE_BREAKPOINT;
  }

  function injectSources(video, mobile) {
    // Clear any previously injected sources
    video.innerHTML = '';

    const webmSrc = mobile
      ? video.dataset.mobileWebm
      : video.dataset.desktopWebm;

    const mp4Src = mobile
      ? video.dataset.mobileMp4
      : video.dataset.desktopMp4;

    // WebM first — smaller file, modern browsers pick this
    if (webmSrc) {
      const webm = document.createElement('source');
      webm.src = webmSrc;
      webm.type = 'video/webm';
      video.appendChild(webm);
    }

    // MP4 second — universal fallback (Safari, older browsers)
    if (mp4Src) {
      const mp4 = document.createElement('source');
      mp4.src = mp4Src;
      mp4.type = 'video/mp4';
      video.appendChild(mp4);
    }

    // Tell the browser to reload with the new sources
    video.load();
  }

  function initHeroVideo() {
    const video = document.querySelector('.hero__video');
    if (!video) return; // exit silently if no hero video on this page

    const mobile = isMobile();
    injectSources(video, mobile);

    // Explicit play() — belt-and-braces for autoplay policy edge cases
    const playPromise = video.play();
    if (playPromise !== undefined) {
      playPromise.catch(function (err) {
        // Autoplay blocked (iOS Low Power Mode, data-saver mode, etc.)
        // Poster image remains visible — this is the correct fallback.
        console.info('Hero video autoplay blocked. Poster shown.', err.message);
      });
    }

    // Handle orientation change on mobile
    // Re-evaluate breakpoint after rotation settles (300ms debounce)
    let resizeTimer;
    window.addEventListener('resize', function () {
      clearTimeout(resizeTimer);
      resizeTimer = setTimeout(function () {
        const nowMobile = isMobile();
        if (nowMobile !== mobile) {
          // Device has crossed the breakpoint — swap sources
          injectSources(video, nowMobile);
        }
      }, 300);
    });
  }

  // Run after DOM is ready
  if (document.readyState === 'loading') {
    document.addEventListener('DOMContentLoaded', initHeroVideo);
  } else {
    initHeroVideo(); // DOM already loaded (deferred script)
  }

})();
Load this script with defer — never with async alone. defer guarantees the DOM is ready when the script runs, and it does not block the poster image from rendering. Example: <script src="/js/hero-video.js" defer></script>
Section 06

Head Tag — Preload

The preload hint must appear in the <head> before any stylesheet. This signals to the browser to begin fetching the poster image at the highest possible priority — making it your LCP element rather than the video itself.

html<head> — insert before stylesheets
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1.0">
  <title>Page Title</title>

  <!-- ✅ POSTER PRELOAD: must be first, before any CSS -->
  <link
    rel="preload"
    as="image"
    href="/assets/images/hero-poster.webp"
    type="image/webp"
    fetchpriority="high"
  >

  <!-- Stylesheets follow after -->
  <link rel="stylesheet" href="/css/hero-video.css">
  <link rel="stylesheet" href="/css/main.css">

  <!-- Script loaded with defer — does not block render -->
  <script src="/js/hero-video.js" defer></script>

</head>
Section 07

PHP Template — WordPress

For WordPress sites, the preload link must be added via wp_head action, and the video HTML goes in the theme's front-page.php or the relevant template file. Never hardcode the preload directly in header.php — use the hook so child themes can override it.

functions.php — Preload Hook

phpfunctions.php
<?php

/**
 * Add hero poster image preload to <head>.
 * Only fires on the front page to avoid loading it everywhere.
 */
function salon_preload_hero_poster() {
    if ( !is_front_page() ) {
        return;
    }
    $poster_url = get_template_directory_uri() . '/assets/images/hero-poster.webp';
    echo '<link rel="preload" as="image" href="' . esc_url( $poster_url ) . '" type="image/webp" fetchpriority="high">' . "\n";
}
add_action( 'wp_head', 'salon_preload_hero_poster', 1 ); // priority 1 = before everything else


/**
 * Enqueue hero video CSS and JS.
 * JS is loaded with defer via wp_enqueue_script().
 */
function salon_enqueue_hero_assets() {
    if ( !is_front_page() ) {
        return;
    }
    wp_enqueue_style(
        'salon-hero-video',
        get_template_directory_uri() . '/css/hero-video.css',
        [],
        '1.0.0'
    );
    wp_enqueue_script(
        'salon-hero-video',
        get_template_directory_uri() . '/js/hero-video.js',
        [],          // no dependencies
        '1.0.0',
        [ 'strategy' => 'defer', 'in_footer' => false ]
    );
}
add_action( 'wp_enqueue_scripts', 'salon_enqueue_hero_assets' );

Section 09

Schema — No Changes Required

No VideoObject schema is needed. The existing LocalBusiness + Organization schema is correct and complete. Adding VideoObject to a decorative background video would violate Google's structured data guidelines, which require schema to accurately represent content the user can interact with.

Google's Search Central documentation states: "VideoObject structured data must be added to a page where users can watch the video." A muted, looping, controlless background video does not qualify as a watch page. Do not add VideoObject schema.

Confirm the existing LocalBusiness schema includes at minimum: name, address, telephone, url, openingHoursSpecification, and image. No further schema additions are required for this video implementation.

Section 10

CDN & Cache Headers

Video files must be served with long-cache headers. Since filenames include a content hash, the URL changes when the file changes — so a 1-year cache is safe.

Nginx Configuration

nginxnginx.conf or site config
# Video and image assets — 1 year cache
location ~* \.(webm|mp4|webp)$ {
    expires 1y;
    add_header Cache-Control "public, max-age=31536000, immutable";
    add_header Accept-Ranges bytes;   # enables range requests for partial video loading
    gzip off;                          # never gzip binary video files — wastes CPU
}

# Correct MIME types (in case not set by default)
types {
    video/webm   webm;
    video/mp4    mp4;
    image/webp   webp;
}

Apache .htaccess

apache.htaccess
<IfModule mod_expires.c>
  ExpiresActive On
  ExpiresByType video/webm  "access plus 1 year"
  ExpiresByType video/mp4   "access plus 1 year"
  ExpiresByType image/webp  "access plus 1 year"
</IfModule>

<IfModule mod_headers.c>
  <FilesMatch "\.(webm|mp4|webp)$">
    Header set Cache-Control "public, max-age=31536000, immutable"
    Header set Accept-Ranges "bytes"
  </FilesMatch>
</IfModule>

# Correct MIME types for video
AddType video/webm .webm
AddType video/mp4  .mp4
AddType image/webp .webp
Accept-Ranges: bytes is required for video. Without it, browsers cannot make partial HTTP range requests, which means the entire video must download before playback begins. Nginx serves this by default; Apache requires the header to be set explicitly.

Chrome DevTools — LCP Element Verification

This test confirms the poster image, not the video, is registered as your LCP element.

devtoolsstep-by-step protocol
1. Open Chrome on the homepage (not incognito — extensions are irrelevant here)
2. Open DevTools: F12 or Cmd+Option+I on Mac
3. Go to the Performance tab
4. Click the circular Record button (top left of the panel)
5. Hard-reload the page: Ctrl+Shift+R (Windows) or Cmd+Shift+R (Mac)
6. Wait for the video to start playing (~3 seconds)
7. Click Stop in the Performance panel

─── CHECKING LCP ─────────────────────────────────────────────
8.  In the Timings row, look for the "LCP" marker (green diamond)
9.  Click the LCP marker — a tooltip appears
10. The tooltip shows the LCP element. It must read:
    Element: <img>  (the poster image)
    URL: /assets/images/hero-poster.webp

    ❌ FAIL if it reads: Element: <video>
       This means the preload is not firing. Debug Section 06.

─── CHECKING CLS ─────────────────────────────────────────────
11. In the Experience row (below Timings), look for red blocks
    labelled "Layout Shift"
12. There must be no Layout Shift events caused by the video
    container loading or resizing.
    ❌ FAIL if a Layout Shift event is triggered in the first
       3 seconds of page load near the hero section.

─── CHECKING VIDEO SOURCE SELECTION ──────────────────────────
13. Go to the Network tab
14. Filter by "Media"
15. Reload the page
16. Confirm only one video file is requested per page load:
    - On desktop: hero-desktop.webm (or .mp4 if WebM not supported)
    - On mobile: hero-mobile.webm (or .mp4 if WebM not supported)
    ❌ FAIL if both desktop and mobile files are requested,
       or if no video file is requested (JS not running).
